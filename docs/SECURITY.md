# Security review and limits

Completed: SQL values use bound parameters; admin DOM uses `textContent`; Worker HTML escapes member fields; verification and access tokens use cryptographic randomness and SHA-256 hashes at rest; tokens expire after 24 hours and confirmation is POST-only. Sessions use HttpOnly, Secure, SameSite=Lax cookies. Public writes require exact Origin and Cloudflare rate-limit binding. Admin routes require a secret bearer token held only in page memory. Multipart bodies are capped before parsing and audio signatures are checked. R2 keys are random, private and never public URLs. D1 unique constraints and an immutable, nonnegative ledger guard duplicate credits and spending.

Worker headers include no-store, no-referrer, nosniff, frame deny and a Permissions Policy. The verification and Worker-hosted member pages also set CSP. The rewards page permits `connect-src 'self'` for authenticated deletion; its `default-src 'none'`, inline script/style rules, frame and base restrictions remain. The additional submission page already permits same-origin fetch and form submission. Verification and access confirmation pages allow only same-origin form submission. Chrome can send `Origin: null` on a legitimate Confirm POST after entering the page from another origin; the Worker accepts that value only when Fetch Metadata reports a same-origin navigation. Cross-site null-origin requests remain blocked. The landing and founder pages permit only their own scripts, Google Fonts and `https://*.workers.dev` API calls; the landing page permits `blob:` for local recording playback. The static privacy page has no active content or remote resources. GitHub Pages cannot set arbitrary response headers through this repository; static pages use a referrer meta tag. Worker-only headers must be checked on the deployed Worker.

Synthetic mode has its own 32+ character secret, requires the public gate to be closed and the privacy flag to be approved, accepts reserved `example.test` identities and marked content, and only accepts a fixed silent WAV fixture. It returns confirmation tokens only to an authenticated request and sends no email. Authenticated cleanup and one-day scheduled cleanup erase active synthetic records and R2 audio; immutable ledger and audit tombstones remain. Session cookies are revoked and cleared on member deletion. Expired access tokens, send cooldown hashes and sessions for deleted members are removed by scheduled cleanup.

Residual limits: founder token is a shared bearer secret rather than individual accounts or MFA. Consider Cloudflare Access before scale. Cloudflare's configured rate limit is a coarse 5 requests/60 seconds; abuse may require Turnstile and operational monitoring. Email/phone are weak identity signals, and phone is not verified. The two-minute recording limit is enforced in the browser; the Worker validates bytes and size but does not decode media duration. R2 and D1 cannot commit atomically; a failure during multi-object deletion may require manual recovery. D1's batch transaction and uniqueness constraints guard duplicate referrals, but local tests cannot prove distributed behavior; controlled synthetic production tests remain required. Scheduled retention processes at most 100 expired submissions and 100 aged synthetic members per run; monitor for backlog. Backup copies may outlive active record deletion. No independent penetration test, healthcare compliance assessment or legal approval has been completed.

Never place credentials in HTML, GitHub Actions variables exposed to the frontend, URLs, issues or comments. Rotate `ADMIN_TOKEN` and `RESEND_API_KEY` in Cloudflare if exposed. Keep R2 public access disabled.
